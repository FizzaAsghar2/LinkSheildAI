# Security model and limitations

The scanner permits only HTTP(S), rejects embedded URL credentials, resolves hostnames before retrieval, blocks non-global addresses, revalidates each redirect target, disables automatic redirects, bounds redirect count, applies request timeouts and response byte limits, and never executes page code. It fetches a bounded number of linked JavaScript resources and analyzes them alongside inline scripts. Bounded decoders and source-specific rules look for media capture, recording, page-lifetime triggers, direct password-field reads, and outbound APIs. Generic cookie/storage/network calls or encoded text alone do not create a high-severity finding. Scores group related findings to limit double-counting, record their factors, and are not probabilities or clean bills of health. Reports are versioned, and earlier reports are marked legacy for rescanning.

**Deployment hardening required:** the current HTTP client independently resolves the host at connection time after validation, leaving a DNS time-of-check/time-of-use gap. For an internet-facing deployment, replace this transport with a resolver-pinned connector and enforce outbound network policy at the host/container layer. The local app is intended for localhost development. Configure CORS origins narrowly and add an authenticated/rate-limited reverse proxy before exposing it to untrusted clients.

Google Web Risk lookup is optional and disabled by default. When explicitly enabled with an API key, the full submitted URL is sent to Google; no reputation provider is contacted by default. No match is not a clean verdict. Dynamic analysis is disabled because an isolated disposable browser and egress restrictions are not provisioned. Therefore this version cannot confirm whether a permission was granted, whether capture started, or whether media was transmitted at runtime. A missing finding does not establish safety. Camera/microphone API references indicate capability or possible permission requests only; capture plus recorder/transport patterns raise the risk classification but still do not prove execution or intent.
