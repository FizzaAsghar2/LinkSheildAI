# Architecture

The React application and Chrome MV3 companion call the same FastAPI service. The API validates input and records a scan; FastAPI background tasks execute the shared static scanner without delaying scan creation. SQLite stores scan state, a JSON report snapshot, and normalized findings, evidence, AI explanations, and scan metadata. The rule engine assigns scores from deterministic finding classes. Each scan then requires Cerebras to summarize the structured scanner findings and coverage; it does not receive the full URL or fetched page source and cannot write the score or verdict. Missing Cerebras configuration or a failed response prevents the scan from completing.

Scanning retrieves bounded HTTP(S) HTML with redirects handled manually, validates each redirect destination, parses forms and embedded resources, and inspects a bounded number of inline and linked JavaScript resources without executing them. Static checks combine optional AST parsing with bounded decoding of common hex, Unicode, base64, and character-code wrappers. High-risk behavior rules require related signals in the same script source; generic cookie, storage, encoding, and network APIs alone do not imply theft. Reports include source coverage, parser status, scanner version, grouped score factors, and a separate verdict. Runtime-loaded code, obfuscation, and browser behavior can remain unobserved. Google Web Risk lookup is optional and off by default; enabling it sends the full URL being scanned to Google. Dynamic analysis stays disabled without a disposable isolated runner.
